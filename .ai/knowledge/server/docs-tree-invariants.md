# Docs 树查询与命令不变量

树导航和树命令只需要文档元数据。若复用详情的全文查询，即使响应没有正文，PostgreSQL 驱动仍会接收并解码正文及文本投影；单行各自可达 8 MiB，分页和同级排序会放大读取量。

`apps/server/src/domains/docs/repository.ts` 的 `findDocument`、同级、祖先和物理子树查询使用元数据投影，`findDocumentWithContent` 仅供需要正文的详情或写后结果使用。活动和回收详情都重新校验已存 profile 1 内容；损坏内容返回固定内部错误，不静默修补或回写。内容规则以 Contract 和内容校验模块为准。

物理遍历包含已回收行，递归携带路径和深度，发现环或既有超深树时按数据损坏处理。先得到并验证物理子树，再将同一 ID 集合用于跨空间批量更新，避免更新阶段另跑无界递归。树深度限制约束的是文档层级，不是正文节点深度；两者不能混用。

`apps/server/src/domains/docs/service.ts` 的命令在取得空间锁后计算最终同级顺序。同父移动只应用最终顺序；维护本命令已变更文档的集合，使搬移或恢复与位置重排重叠时，文档版本仍只增加一次。响应携带的版本必须与提交后的记录一致，下一次条件写入才能继续使用它。表职责与删除批次规则集中于 `.ai/databases/data-model.md`，此处不重复定义。

回收站的顺序是删除时间降序、ID 升序，续页条件必须分别表达两个方向。同一毫秒的回收记录按 ID 向后翻页；不能用整元组的小于比较。所有分页游标都属于不可信输入，内部 ID 在参与 PostgreSQL UUID 比较前须先校验，坏游标返回固定 400，而不是将驱动类型错误当作内部故障。

验证这些行为时，从真实业务入口执行命令，比较响应与持久版本、核对最终同级顺序；查询投影通过真实数据库调用记录验证。规模测试中的短正文不能独自证明正文读取量受控。测试与命令范围遵守 `TESTING.md`。
